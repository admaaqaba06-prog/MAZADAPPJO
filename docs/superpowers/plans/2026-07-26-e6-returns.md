# E6 — Returns Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Let a buyer, at the receive step, either approve (release escrow) or open a not-as-described/damaged return with photos — escrow stays locked, seller + admin are notified, and admin resolves via the existing dispute machinery (refund from still-locked escrow, or deny).

**Architecture:** A `requestReturn` callable freezes the order into `disputed` with a structured `returnClaim` (no money moves). Buyer UI splits the shipped-order receive step in two. Seller sees the claim + accepts/contests. Admin's existing DisputesSection resolves it: refund → existing `refundOrderEscrow`, deny → `releaseOrderEscrow`; resolution stamps `returnClaim.status` + notifies the buyer. Two new notify events.

**Tech Stack:** React 19 + Vite + TS + Firebase (Functions CommonJS, Firestore, Storage), Vitest.

## Global Constraints

- `requestReturn` and all E6 server code must make **ZERO wallet/ledger writes** — a return only changes order status + writes the claim. Money moves ONLY through the existing audited `refundOrderEscrow` / `releaseOrderEscrow` callables at admin resolution.
- Money-path/notification code must **never throw** into a committed transaction (E5 contract); `notify()` already swallows errors.
- `functions/returns.js` and `functions/notify.js` must be **pure** (no firebase imports) — root Vitest loads them (#138 guard).
- Reasons enum is exactly `not_as_described | damaged`. Photos: 1–6, required.
- Return is available ONLY on `status === 'shipped'` (the live receive state).
- Test globs: `src/**/*.test.ts(x)`, `functions/**/*.test.js`. Co-locate tests. Functions test files need `import { describe, it, expect } from 'vitest'` (no globals).
- Arabic-primary copy; bilingual UI labels; smooth ease-out motion.
- Worktree `/tmp/mazadjo-e6`, branch `feat/e6-returns` (created off origin/main incl. E5; spec committed).

```js
'use strict';
// Pure return-claim helpers. NO firebase deps (root Vitest loads this; #138).

const RETURN_REASONS = ['not_as_described', 'damaged'];
const MAX_PHOTOS = 6;

function invalid(msg) {
  const e = new Error(msg);
  e.code = 'invalid-argument';
  return e;
}

function buildReturnClaim(input, nowMs) {
  const reason = input && input.reason;
  if (!RETURN_REASONS.includes(reason)) throw invalid('invalid reason');
  const description = String((input && input.description) || '').trim();
  if (!description) throw invalid('description is required');
  const photoUrls = Array.isArray(input && input.photoUrls) ? input.photoUrls.filter(Boolean) : [];
  if (photoUrls.length < 1) throw invalid('at least one photo is required');
  if (photoUrls.length > MAX_PHOTOS) throw invalid(`at most ${MAX_PHOTOS} photos`);
  return {
    reason, description, photoUrls,
    sellerPaysReturnShipping: true,
    status: 'open',
    createdAt: nowMs,
  };
}

function canRequestReturn(order) {
  if (!order || order.status !== 'shipped') return false;
  if (order.returnClaim) return false;
  return true;
}

module.exports = { RETURN_REASONS, MAX_PHOTOS, buildReturnClaim, canRequestReturn };
```
